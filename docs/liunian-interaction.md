## 一、合盘要不要纳入大运流年

**结论：要纳入，但只能作为独立「动态层」，绝不并入 160 分总分。**

### 三条核心考量

**1）可比性 —— 不能并入总分的第一理由**

160 分体系是**静态**的：两人出生那一刻就定死，任何时候打开都是同一个数。
这是它的核心价值。一旦分数含年份，今天 112、明年 98，用户读到的不是"今年要注意"，
而是"我们是不是不合了"——**分数是"缘分刻度"，流年是"运势读数"，两种量纲混在一起，
哪个都读不准**。

更硬的约束：档位 `118 / 103 / 85` 是在 400 对**静态盘**上按 p90/p55/p15 标定的
（`__tests__/hepanCalibration.test.ts` 用区间断言钉住）。分数一旦随年份漂移，
锚点每天都在动、测试必然失效——那不是 bug，是提醒你别把动态量塞进静态量表。

**2）共同盘不存在 —— 技术理由**

大运是**各人自己的**。A 走甲子、B 走己亥，两者之间不存在中立的"关系盘"。
要压成单一分数，就得人为规定"A 的大运权重 × B 的大运权重"——这个权数既无经典依据，
样本上也标定不出来（2 人 × N 步大运，自由度爆炸）。
所以动态层只能出**档位 + 双视角描述**，不能出**单一分数**。

**3）静态盘答不了"什么时候" —— 必须纳入的理由**

静态合盘只能说"你们合不合"，说不了"今年该不该推进、哪年是坎"。
桃花的起落、配偶宫被冲被合、双方大运同向还是相悖，恰恰是最能落地的信息。
**用户问"今年"，给一张与年份无关的报表，就是答非所问。**

### 分层结构

| 层 | 内容 | 是否随年份变 |
|---|---|---|
| 先天缘分（静态） | 160 分：八字六项 + 紫微两项 | 不变，跨年份可比 |
| 流年互动（动态） | 关系年度主题 / 风险点 / 契机点 | 逐年变化 |

类比：静态层是"体检报告"，动态层是"天气预报"。互换就两头失真。

## 二、判据

### 1. 地支层（判据唯一出口：`utils/diZhiRelations.ts`）

- **六冲**：子午、丑未、寅申、卯酉、辰戌、巳亥
- **六合**：子丑、寅亥、卯戌、辰酉、巳申、午未
- **六害（穿）**：子未、丑午、寅巳、卯辰、申亥、酉戌
- **相刑**：子卯；寅巳申（两两皆刑）；丑戌未（两两皆刑）。自刑（辰午酉亥重复）判据是"同支出现两次"，在 `shenShaPower.branchRelationsOf` 里，**不属于岁运层**
- **三合局**：申子辰水、亥卯未木、寅午戌火、巳酉丑金（三支齐 = 全合；两支 = 半合，含旺支子午卯酉者力量更强）
- **三会方**：寅卯辰木、巳午未火、申酉戌金、亥子丑水（力量强于三合）

**⚠️ 优先级：冲 > 合 > 刑 > 害（只取最强一条）**

地支里确实存在"既冲又刑""既合又刑"的组合：

| 组合 | 同时属于 | 本项目取 |
|---|---|---|
| 丑未 / 寅申 | 六冲 + 三刑 | 六冲 |
| 巳申 | 六合 + 三刑 | 六合 |
| 寅巳 | 相刑 + 相害 | 相刑 |

两条一起输出会让"这一柱被怎样引动"变得含糊（冲是"动"、刑是"磨"，处理方式不同）。
优先级与 `shenShaPower` 的制化系数顺序一致（冲 0.40 < 合 0.55 < 刑 0.75 < 害 0.80）。
判据由 `__tests__/liunianInteraction.test.ts` 的全量 12×12 扫描钉死。

### 2. 伏吟 / 反吟

- **伏吟**：岁运与命局某柱**地支相同**。干支全同 = 全伏吟（主旧事重演）；仅地支同 = 支伏吟（同一类问题再来一次）。
  ⚠️ 这不是"自刑"——自刑指命局四柱内部同支重复，两者语义不同，不要合并。
- **反吟**：**天克地冲**（天干五行相克 且 地支相冲），变动的极值。反吟柱不再另列六冲（重复）。

### 3. 天干层

- **天干五合**：甲己、乙庚、丙辛、丁壬、戊癸
- **十神**：`wuXingRelations.tenGodOf`（同阴阳为偏、异阴阳为正）

### 4. 桃花（按**岁运地支**起）

- **红鸾**：子年卯、丑年寅、寅年丑、卯年子……（自卯位起逆行）
- **天喜**：红鸾的对冲位（子年酉、午年卯）
- **咸池**：按年支三合局取——申子辰见酉、寅午戌见卯、巳酉丑见午、亥卯未见子

⚠️ **只在流年（`era='year'`）与大运（`era='decade'`）产出**。流月 / 流日的颗粒度过细，
"某月红鸾落哪柱"没有实务意义，硬输出只会变成噪声——`era='month' | 'day'` 时 `peach` 恒为 `[]`。

## 三、时间尺度（`era`）：同一套判据，四种时间词

大运 / 流年 / 流月 / 流日**走同一个函数**（`analyzeGanZhiInteraction`）——它们对命局的作用机制
完全相同，区别只在时间跨度。**不要为大运另写一套**。

`era` 只影响措辞，不影响判据（有测试钉住：四种尺度的 `hits` / `spousePalace` 必须完全一致）。

| `era` | 时间词（`TW`） | 兜底句（`SPAN`） | 岁运称呼（`YU`） | 一段时间（`PERIOD`） |
|---|---|---|---|---|
| `'year'`（默认） | 今年 | 属平顺之年 | 流年 | 这一年 |
| `'decade'` | 这十年 | 属平顺的十年 | 大运 | 这十年 |
| `'month'` | 本月 | 属平顺之月 | 流月 | 这个月 |
| `'day'` | 今日 | 属平顺之日 | 流日 | 这一天 |

四张表集中在 `liunianInteraction.ts` 顶部（`ERA_TIME_WORD` 等），**必须成组维护**。

⚠️ **为什么必须区分**：把流年措辞套到别的尺度上不会报错，只会写出
「这步运**今年**最动」「流日甲木为财，**今年**感情机会与家庭议题容易同时出现」这种句子。
本模块最容易出的错就在这里，所以四项各有一组回归用例。

### 各尺度的调用方

| 尺度 | 调用方 | label | 备注 |
|---|---|---|---|
| 流年 | `analyzeLiunianFlow(year, chart, ganZhi)` | `2026年` | 八字页流年卡；含桃花 |
| 大运 | `analyzeDayunFlow(ganZhi, chart)` / `buildDayunReadings(..., chart)` | `7~16岁大运` | ⚠️ 不得写死「当前大运」——列表里过去/未来的运都会自称当前 |
| 流月 | `buildLiuYueList({..., pillars, dayGan, yongShen, strengthLevel, gender})` | `2026年10月` | 与「大运地支 vs 月令天干」后缀并行，`interaction` 单独字段 |
| 流日 | `buildLiuRiList({year, month, ...})` | `2026年10月13日` | 自 `Bazi.tsx` 的 `handleLiuRi` 迁入（原先页面内联，还自带一份 `tgWx` 五行表） |

⚠️ **流月 / 流日的用神旺衰必须在 `useMemo` 里取，不能放 `handleCalc`**：
`yongShenRec` / `strengthAnalysis` 是 `useMemo`，`handleCalc` 执行时尚未产出
→ 喜忌定向整层静默缺失，不报错，只是所有月份都退回 `neutral`。这是最难发现的失败模式。

## 五、喜忌定向（方向性判据）

```
用神（yongShen 含该五行） → good
忌神（deriveJiShen 推出） → bad
其余                     → neutral（中性：只报"有变动"，不定吉凶）
```

**⚠️ 破坏性作用（冲 / 刑 / 害）的吉凶要取反**：

> 冲掉**忌神**是好事（去掉不利因素），冲伤**用神**才是坏事。
> 若直接沿用上面映射，"午冲子"在子水为忌神的盘上会被判成凶——**方向是反的**。

合（六合 / 三合 / 三会）是牵引性作用，**不取反**：合住用神得助为吉，合住忌神被牵制为凶。

未传 `strengthLevel` 时一律 `neutral`——保证旧调用方行为不变
（与 `hepan.xiJiAdjust` 的整体门控思路一致）。

## 六、合盘动态层（`utils/hepanFlow.ts`）

### 判据（5 条，全部可解释）

| # | 判据 | 加权 |
|---|---|---|
| 1 | 双方配偶宫（日支）被如何引动 | 都合 +2；都冲 −2；一冲一合（错位） −1；单边 −1/+1 |
| 2 | 感情星同时被引动：男看财（妻星）、女看官杀（夫星） | 双动 +2；单动 +1 |
| 3 | 双方都走"自我优先"之气（男比劫 / 女食伤） | −1 |
| 4 | 双方当前大运对各自命局偏顺 / 偏逆 | 都顺 +1；都逆 −1；一顺一逆 → 只出提示不计分 |
| 5 | 流年红鸾 / 天喜落任一方命局 | +1；咸池同时落双方 −1 |

### 档位阈值

```
score >= 3  → 顺（推进之年）
score <= -3 → 需留意（磨合之年）
其余        → 平（平稳之年）
```

⚠️ 改任一加权或阈值，必须同步 `__tests__/hepanFlow.test.ts`——
那里钉了"双方都合配偶宫 → 出「同时被合」"与"双方配偶宫都被冲 → 出「同时被冲」"两类边界，
以及**交换双方输入的对称性**（档位与主题必须不变）。

### 结构性保证

- 返回结构里**没有**任何分数字段；`HEPAN_MAX_SCORE` 仍为 160，档位体系不变。
- 动态层的 `notice` 必须向用户说明"本层不参与总分"。
- 双方输入交换后，`level` 与 `theme` 必须相同（分数对称原则的延伸）。

## 七、大运解读如何接入（`utils/dayunReading.ts`）

大运解读的「阶段 × 十神关系」30 条文案**一个字都没改**——互动是**并行新增**的字段，不是替换。
原因是那批文案带着「60 岁后措辞黑名单」与「同阶段不重复」两条约束，混进去会让两套逻辑互相污染。
页面上两者分块展示。

- `buildDayunReadings(steps, dayGan, currentAge, nominalAge, chart?)` 第 5 参 `chart` 传入后，
  每步大运多出 `interaction` 与 `interactionNote`；**不传则行为与接入前完全一致**（既有调用方零影响）。
- `interactionNote` 由 `buildInteractionNote(flow, stage)` 生成：按
  `KIND_WEIGHT`（反吟 > 冲/合 > 三合三会/伏吟 > 天干五合 > 刑 > 害）取前 3 处，只讲最重要的。
- ⚠️ **晚年阶段（`retire` / `elder`）的领域名必须改写**：`LATE_DOMAIN_REWRITE` 把
  「事业与家庭根基」→「家庭与日常安排」。另设 `LATE_FORBIDDEN` 词表做双保险——
  真漏过就退回中性表述，绝不输出事业 / 求财类措辞（判据，不是修辞，有测试钉着）。
