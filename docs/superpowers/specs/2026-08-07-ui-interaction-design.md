# 爻一爻 UI 与交互优化设计文档

- 日期：2026-08-07
- 状态：已获用户确认（2026-08-07）
- 前置：白屏问题已解决（6.9MB 版验证正常）

## 背景与目标

用户反馈：整体页面需适应不同手机尺寸；页面拥挤；交互逻辑反常，**特别是八字排盘与紫微斗数页**。已确认优化方向为方案 B（针对性逐项优化，12 项修复清单）。

## 现状问题清单（基于代码分析）

### 八字页（src/pages/Bazi.tsx）
1. 手机端已有 2×2 四柱卡片，下方仍渲染同一份 `minWidth:480` 竖表 → 必然横向滚动（冗余）
2. 神煞白话解释用 `Tooltip` → 移动端无 hover 不可达
3. 表单校验靠 `message.warning` toast，非 antd rules；农历模式无闰月选项、无日期合法性校验
4. 10+ 个 `CollapsibleCard` 全部默认折叠 + 同组手风琴互斥 → 核心内容需逐个点开
5. 流月 InputNumber onChange 即算 + 旁边冗余「查看流月」按钮（双入口）；流年/流日需填数+点按钮（3 次点击）
6. 流日网格 `Col span={3} minWidth:80` → 375px 必溢出，外层又套滚动 → 双向滚动
7. 结果区无「重新排盘/修改信息」入口，改参数需滚回顶部

### 紫微页（src/pages/Ziwei.tsx）
8. 十二宫详解固定 4 列 CSS Grid → 375px 每格约 80px 挤爆；图例 Tag 挤占标题栏
9. 公历/农历切换 `resetFields(['month','day'])` → 已填月日被清空
10. 无出生地输入，`longitude: 120` 硬编码；而八字页有 Cascader + 真太阳时校正 → 两页能力不一致，紫微精度受限
11. 解读文案 `Math.random()` 选 verdict → 折叠重开/重渲染同宫文字会变，用户以为结果不稳定
12. SVG 星图字号固定 9-15px，375px 下缩至约 65% 可读性差（缓解项）

### 共享
- 结果默认全折叠 + 手风琴互斥
- 两页表单校验能力不一致

## 设计方案（4 节 12 项）

### 第 1 节｜移动端响应式适配（#1/#6/#8）
- **八字竖表**：`isMobile` 时隐藏竖表（仅保留 2×2 卡片）；桌面端保留
- **流日网格**：移动端 8 列 → 7 列周历式（`Col span={7}`，去 minWidth），消除横向滚动；纵向滚动保留
- **紫微宫格**：新增 `isMobile` 判断（`window.innerWidth <= 768`，仿 Bazi.tsx），十二宫详解移动端 2 列、≥768px 4 列；卡片内字号/间距随列数自适应

### 第 2 节｜表单与校验（#3/#10/#12）
- 两页出生信息表单改 antd `rules` 内联校验（红字定位），补日期合法性检查（如 2 月 30 日、闰月与月份匹配）
- 农历模式补闰月选择（两页一致）
- 紫微页补省市区 Cascader 出生地（复用 `cn-division` + `getCityLng`），排盘用 `getTrueSolarHour` 真太阳时校正

### 第 3 节｜结果区交互（#2/#4/#5/#7/#9/#11）
- `CollapsibleCard`：大运卡默认展开；去掉同组手风琴互斥（允许多开）或按内容块重新分组
- 流月去双入口：InputNumber 选择即算，移除「查看流月」按钮；流年/流日统一选择即算
- 结果区顶部加「修改信息」按钮：平滑滚动回表单并高亮
- 神煞解释 `Tooltip` → `Popover trigger="click"`
- 紫微公历/农历切换不 reset 月日（仅更新月份选项）
- 紫微解读 verdict 改确定性选择（按宫位名哈希），重渲染文案稳定

### 第 4 节｜交付
- 逐项修复走测试/构建验证；`npm run build:android` 重新打包 `爻一爻-debug.apk`
- 桌面端（GitHub Pages）不受影响（改动为移动端优先增量）

## 验收标准
1. 375px 宽度下八字页无横向滚动（四柱竖表隐藏、流日 7 列）
2. 紫微十二宫在 375px 下 2 列可读、无溢出
3. 两页表单非法日期/闰月错误内联红字提示
4. 紫微排盘结果与八字页使用同一出生地/真太阳时逻辑
5. 大运卡默认展开；多个折叠卡可同时展开；流月无双入口
6. 紫微切换公历/农历保留月日；折叠重开解读文案不变
7. 神煞解释在移动端可点击查看
8. `爻一爻-debug.apk` 重新打包成功
