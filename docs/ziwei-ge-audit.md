# 紫微斗数成格判定 · 审计报告

> 审计对象：`src/utils/ziweiGe.ts`（11 格 + 4 条破格 + 3 个夹宫格）
> 样本：3024 盘（1990–2010，每月 3 天 × 4 时辰），走与 `Ziwei.tsx` 完全相同的管线
> （`ziwei.bySolar` → `enrichGongData` 补甲级辅星 → `recalcSihua` 重算全书画四化 → `analyzeZiweiGe`）。
> 日期：2026-10-17。

---

## 一、结论先行

1. **有缺失，而且缺得多**：经典格命中过的只有 11 个，缺了十余个常用格（君臣庆会、禄马交驰、巨日同宫、武贪同行、石中隐玉、月朗天门、日照雷门、明珠出海……）。
2. **有逻辑错误，而且有一条是"总闸"级的**：三条全局破格规则把 **67.8% 的盘清成"无格局"**；其中 **41.7% 的盘结构上完全够格**，只是被破格规则拦掉。
3. 另有 4 处一致性问题（夹宫格绕过全局破格、星源不统一、命名误导、测试名与口径相反），以及 2 处口径过宽（火贪落宫、加冕不认禄存）。

**§3.2 为什么不是"连坐"而是"分层"**：实测 **昌曲夹结构成立的盘 124/124 全部带破格**
（昌曲距离 2 只出现在寅/午/戌时，这些时辰的空劫/火星落点恰好压在三方四正）。
若让夹宫格也受破格约束，无格率会从 67.8% 涨到 76.3%（昌曲夹命 84→0、火贪 66→9），
等于删掉这个功能。改为：破格文案明确写「→ 主星格不入格 / 主星格受破」，
重破盘上的夹宫格与火贪/铃贪在理由末尾加「（主星格已受破，此格属 XX 层，力度打折）」。
最终分布与修改前一致（无格 67.8%），148 张"只有夹宫格"的盘不再出现自相矛盾文案。

## 三、逻辑错误

### 3.1【总闸级】三条全局破格一刀切，惩罚不对称

现状：`hasJi || sha≥2 || kong≥2 || 羊陀夹忌` 任一成立 → 10 个主星格**全部不入**。

三个问题：

1. **不区分落宫**。化忌在命宫、在迁移（冲命）、在财帛，分量完全不同；现在只要有 1 颗生年化忌落在三方四正的任意一宫，就判"格不成立"。16.3% 的盘仅因这一条被清空。
2. **与「加冕分层」自相矛盾**。同一份口径里：缺吉星、缺四化引动 → 只降层次（reasons 注明）；但一颗化忌 → 直接不成格。**加冕的缺失比破格轻得多，惩罚却不成比例**。
3. **煞星计数不看组合**。擎羊+陀罗（羊陀夹命，凶）与 火星+铃星（火铃同宫，可发）被同等计为"煞 2 颗"。20.8% 的盘仅因这一条被清空。

中州派实际用法：化忌、煞星是**减色/带疵**，只有「忌冲命 + 煞重 + 空劫」叠加或特定结构（羊陀夹忌、刑囚夹印）才谈"破"。当前实现把"减色"升级成了"否决"。

### 3.2 夹宫格与火贪/铃贪绕过全局破格

- 148 盘已判定"格局受破"，却仍输出 `昌曲夹命格 / 魁钺夹命格`；
- 110 盘同样输出 `火贪格 / 铃贪格`。

结果页面上会同时出现「煞星达 2 颗，格局受破」与「昌曲夹命格：文昌文曲分居两侧，且四化引动」——**自相矛盾的文案**。文档写的是"命中则主星格一律不入"，夹宫格与火贪不属于主星格，字面上没违约，但用户看不出这个区别。

### 3.3 `majorNames` 名不副实

```ts
const majorNames = sifangStars.filter(s => !SHA_STARS.includes(s.name) && !KONG_STARS.includes(s.name)).map(s => s.name);
```

它实际是"**三方四正除六煞外的一切星名，含昌曲辅弼魁钺禄存**"。当前各判据只拿它比主星名，功能没错；但名字暗示"主星集合"，维护时极易误用（例如将来写 `majorNames.includes('文昌')` 会莫名成立）。

### 3.4 羊陀夹忌的星源与其它分支不一致

该分支读 `g.minorStars`（字符串数组），其余分支读 `minorStarDetails`（带四化的对象）。当前 `enrichGongData` 两边同步 push，所以能跑；一旦某条链路只产 `minorStarDetails`（例如合盘精简链路），夹忌判定会**静默失效**且没有任何报错。

### 3.5 夹宫格「须禄权科引动」的从严是名义上的

`hasLuQuanKe` 只要求三方四正出现**任意一颗**禄/权/科。实测约七成盘满足——这个"从严"几乎不筛人。文档里"刻意从严"的说法与实测不符。

### 3.6 测试名与现行口径相反

`ziweiGe.test.ts` 的 `杀破狼缺四化引动 → 不成格`：在 2026-09 分层口径下，"缺四化"只降档、不应不成立；该用例实际是靠「命宫擎羊 + 财帛陀罗 = 煞≥2」通过的。名字在骗后来人。

### 3.7 潜在隐患：身宫依赖 `isShenGong`

`buildZiweiChart`（`personChart.ts`，合盘/对比链路）产出的宫位对象**没有 `isShenGong`**。目前 `analyzeZiweiGe` 只在 `Ziwei.tsx` 调用（那里手动补了该字段），所以没炸；但那两条链路若要复用成格判定，杀破狼的"命身坐杀破狼"条件会静默退化。

## 四、口径过宽（非硬错，需拍板）

1. **火贪/铃贪允许落在迁移**：实测落宫 = 命宫 48、官禄 41、迁移 30、财帛 21 → **51% 不在命宫也不在财帛**。中州派火贪多论命/财/官，现在连迁移也算，等于再加宽一档。
2. **加冕不认禄存**：`hasLuQuanKe` 只查四化（禄/权/科），不认禄存。传统"吉星会照"含禄存、天马；现在三方有禄存但无四化 → 不加冕。
3. **日月并明的庙旺区间偏宽**：现用"太阳在寅卯辰巳午 + 太阴在酉戌亥子"，等于"两星皆庙旺且会照"。经典日月并明多指太阳巳/太阴酉（或卯/亥）一类固定落点。当前是广义版，可接受但要标口径。

## 五、缺失的经典格（结构命中率实测）

以下条件是"只看结构、不看破格"的命中率，用于判断补进去会不会成为死格：

| 格局 | 条件 | 命中率 |
|---|---|---|
| 日月反背 | 太阳落戌亥子 + 太阴落卯辰巳 | 17.8% |
| 禄马交驰 | 三方四正同时有禄存与天马 | 14.6% |
| 双禄朝垣 | 三方四正有禄存 + 化禄 | 11.2% |
| 君臣庆会 | 紫微坐命 + 左右昌曲魁钺 ≥2 会照 | 5.5% |
| 科权禄夹命 | 禄/权/科 分居命宫两侧 | 4.3% |
| 明珠出海 | 命宫未宫空宫 + 三方会太阳太阴 | 1.7% |
| 巨日同宫 | 太阳+巨门同坐命宫 | 1.6% |
| 武贪同行 | 武曲+贪狼同坐命宫 | 1.5% |
| 马头带箭 | 擎羊坐命于午 | 1.5% |
| 石中隐玉 | 巨门单星坐命于子/午 | 1.3% |
| 日照雷门 | 太阳坐命于卯 | 1.0% |
| 月朗天门 | 太阴坐命于亥 | 0.8% |
| 刑囚夹印 | 天相被廉贞与擎羊相夹 | **0%** |

**最重要的一条缺口是「君臣庆会」**：紫微坐命是紫微斗数里最受关注的结构，但现在若不成紫府同宫/紫府朝垣，紫微坐命**一个格都没有**。而"紫微无左右为孤君"恰恰是要讲的重点。

**「刑囚夹印」不是漏了，是结构上不存在**：廉贞与天相的距离恒为偶数（4 或 6 或 8…），永远不可能相邻，也就无法相夹。这条要写进文档，防止以后有人"补"一个永远不成立的格。

## 六、修复建议（按优先级）

### P0 · 一致性与口径修正（不补格，先把逻辑弄对）

1. **破格分级**，不再一刀切：
   - 硬破（格不成立）：羊陀夹忌；化忌**坐命或冲命（迁移）**；煞星≥3 或「羊陀夹命」；空劫**同宫**。
   - 减色（仍成格，写进 breakReasons/reasons）：化忌在财帛/官禄；煞星 1~2 颗；空劫分居。
2. **夹宫格、火贪/铃贪与主星格口径统一**：重破盘不再输出任何吉格（或反之都输出并注明减色）——二选一，不要一半受一半不受。
3. `majorNames` 更名（`sifangNonShaxing`）或拆成 `majorOnly`；羊陀夹忌统一读 `minorStarDetails`。
4. 修正误导性测试名；补一条"生产链路无 `isShenGong` 时身宫条件安全退化"的用例。

### P1 · 补格（按知名度与命中率排序）

君臣庆会 → 禄马交驰 → 双禄朝垣 → 科权禄夹命 → 巨日同宫 → 武贪同行 → 石中隐玉 → 月朗天门 → 日照雷门 → 明珠出海 → 马头带箭。日月反背 17.8% 命中率虽高，但属凶格，文案须慎（讲"外部环境与内在期待的错位"，不作恐吓）。

每格都要配套：`geNames` + `reasons`（成格理由，绑盘面事实）+ 页面文案，不能只加名字。

### P2 · 需口径拍板

- 火贪/铃贪是否收窄到命/财/官（不含迁移）；
- 加冕是否把禄存计入"吉星会照"；
- 日月并明是否收紧到经典固定落点。

## 七、改动会影响什么

- 破格分级 → 有格盘从 32.2% 升到 **约 74%**（三条全放宽的上限），实际取分级后预计 50%~65%。这是**产品观感的大改**，不是小修：需要主人先定口径。
- 补格只增不减，与破格口径解耦，可独立上线。
- 不影响八字侧任何模块；不影响合盘 200 分锚点（紫微在合盘只占 2 项×20 分，且合盘不调用 `analyzeZiweiGe`）。
